## 1. 🏆 Real-World Software Engineering & Bug-Fixing Benchmarks

### 1.1 Princeton University SWE-bench
* **Institution:** Princeton NLP & University of Chicago
* **Size:** 2,294 task instances pulled from real merged pull requests across 12 popular open-source Python repositories (including **Django**, **Flask**, **SymPy**, **scikit-learn**, and **Requests**).
* **Format:** Git patches, issue descriptions, and verification test suites.
* **Relevance:** This is the industry-standard benchmark for AI agents solving multi-file software engineering tasks. DEV-TRACE’s Django and Flask incident challenges closely mirror the SWE-bench evaluation methodology.
* **Direct Links:**
  * Official Website: [https://www.swebench.com/](https://www.swebench.com/)
  * GitHub Repository: [https://github.com/princeton-nlp/SWE-bench](https://github.com/princeton-nlp/SWE-bench)
  * Research Paper (ICLR 2024): [SWE-bench: Can Language Models Resolve Real-World GitHub Issues?](https://arxiv.org/abs/2310.06770)

### 1.2 Defects4J Benchmark
* **Institution:** University of Washington & University of Massachusetts Amherst
* **Size:** 835 real, reproducible bugs from 17 open-source Java projects with comprehensive JUnit test suites.
* **Relevance:** Benchmarks automated test execution and bug localization, matching DEV-TRACE’s Spring Boot and Eclipse Temurin Java 17 test containers.
* **Direct Links:**
  * GitHub Repository: [https://github.com/rjust/defects4j](https://github.com/Defects4J/defects4j)
  * Paper (ISSTA): [Defects4J: A Database of Existing Faults to Enable Controlled Studies](https://dl.acm.org/doi/10.1145/2610384.2628055)

## 2. 🤖 AI-Generated Code vs. Human-Written Code Benchmarks

These datasets contain programming challenge solutions generated by Large Language Models (GPT-4, Claude 3.5, Gemini 2.0) compared with human submissions. DEV-TRACE uses these datasets to identify AI code generation patterns (syntactic boilerplate, generic variable naming, over-modularization).

### 2.1 OpenAI HumanEval Benchmark
* **Publisher:** OpenAI
* **Size:** 164 hand-crafted algorithmic challenges with function signatures, docstrings, and comprehensive test suites.
* **Relevance:** The baseline benchmark for zero-shot functional correctness and evaluating canonical LLM solution templates.
* **Direct Links:**
  * GitHub Repository: [https://github.com/openai/human-eval](https://github.com/openai/human-eval)
  * Hugging Face Hub: [https://huggingface.co/datasets/openai_humaneval](https://huggingface.co/datasets/openai_humaneval)
  * Paper: [Evaluating Large Language Models Trained on Code](https://arxiv.org/abs/2107.03374)

### 2.2 Google Research MBPP (Mostly Basic Python Problems)
* **Publisher:** Google Research
* **Size:** 974 short Python programming problems designed for junior-to-intermediate developers.
* **Relevance:** Standard benchmark for verifying procedural correctness across core data structures and standard libraries.
* **Direct Links:**
  * GitHub Repository: [https://github.com/google-research/google-research/tree/master/mbpp](https://github.com/google-research/google-research/tree/master/mbpp)
  * Hugging Face Hub: [https://huggingface.co/datasets/google-research-datasets/mbpp](https://huggingface.co/datasets/google-research-datasets/mbpp)

### 2.3 UC Berkeley APPS Benchmark
* **Authors:** Dan Hendrycks et al. (UC Berkeley & Columbia)
* **Size:** 10,000 coding problems across Interview, Beginner, and Competition tiers with 131,836 test cases.
* **Relevance:** Directly models technical interview platforms (LeetCode, HackerRank, Codeforces).
* **Direct Links:**
  * GitHub Repository: [https://github.com/hendrycks/apps](https://github.com/hendrycks/apps)
  * Hugging Face Hub: [https://huggingface.co/datasets/codeparrot/apps](https://huggingface.co/datasets/codeparrot/apps)
  * Paper (NeurIPS 2021): [Measuring Coding Challenge Competence with APPS](https://arxiv.org/abs/2105.09938)

### 2.4 Google DeepMind CodeContests
* **Publisher:** Google DeepMind
* **Size:** 13,000+ competitive programming problems gathered from Codeforces, CodeChef, and HackerEarth, complete with edge-case tests.
* **Relevance:** Benchmarks algorithmic efficiency ($O(N)$ vs $O(N^2)$), memory limits, and timeouts.
* **Direct Links:**
  * GitHub Repository: [https://github.com/google-deepmind/code_contests](https://github.com/google-deepmind/code_contests)
  * Hugging Face Hub: [https://huggingface.co/datasets/deepmind/code_contests](https://huggingface.co/datasets/deepmind/code_contests)

### 2.5 HumanEval-X (Multi-Language Benchmark)
* **Institution:** Tsinghua University (THUDM)
* **Size:** Hand-crafted benchmarks translated across 5 programming languages: Python, C++, Java, JavaScript, and Go.
* **Relevance:** Directly tests DEV-TRACE’s multi-language sandbox engines (GCC C++, Eclipse Temurin Java, Node/Express, and Python).
* **Direct Links:**
  * Hugging Face Hub: [https://huggingface.co/datasets/THUDM/humaneval-x](https://huggingface.co/datasets/THUDM/humaneval-x)
  * GitHub: [https://github.com/THUDM/CodeGeeX](https://github.com/THUDM/CodeGeeX)

## 3. 🔍 Code Plagiarism & Developer Process Telemetry Corpora

### 3.1 PAN SOCO (Source Code Plagiarism Detection Corpus)
* **Organizer:** PAN Workshop at CLEF / FIRE
* **Languages:** C, C++, and Java.
* **Format:** Real student code submissions containing verified instances of cross-plagiarism, refactoring, and code obfuscation.
* **Relevance:** Used to evaluate lexical similarity, AST clone detection, and uncredited solution sharing.
* **Direct Links:**
  * PAN Webis: [https://pan.webis.de/data.html](https://pan.webis.de/data.html)
  * Research Paper: [Overview of the SOCO Task on Detection of Sourced Code Plagiarism](https://ceur-ws.org/Vol-1260/paper1.pdf)

### 3.2 ProgSnap2 Educational Telemetry Standard
* **Organization:** CS Educational Research Community (ACM SIGCSE / ITiCSE)
* **Format:** Standardized schema capturing every code edit event, save action, compile error, and test suite execution.
* **Relevance:** Directly inspired DEV-TRACE’s session event schema (`FILE_OPEN`, `PASTE_DETECTED`, `FOCUS_LOST`, `EXECUTION_RESULT`).
* **Direct Links:**
  * GitHub Specification: [https://github.com/CSSER/ProgSnap2](https://github.com/CSSER/ProgSnap2)
  * Paper: [ProgSnap2: A Standardized Format for Programming Process Data](https://dl.acm.org/doi/10.1145/3304221.3319782)

### 4.3 Automated ML Feature Extraction Script (Python)

To convert native telemetry sessions into Pandas / Scikit-learn feature vectors:

```python
import json
import pandas as pd

def extract_features(db_path="src/data/db.json"):
    with open(db_path, "r", encoding="utf-8") as f:
        data = json.load(f)
    
    rows = []
    for session in data.get("telemetry", []):
        events = session.get("events", [])
        
        pastes = [e for e in events if "PASTE" in e.get("type", "")]
        focus_losses = [e for e in events if "FOCUS" in e.get("type", "") or "TAB_SWITCH" in e.get("type", "")]
        tests = [e for e in events if "EXECUTION" in e.get("type", "")]
        
        total_pasted_chars = sum(
            e.get("meta", {}).get("pasted_length", 0) or e.get("meta", {}).get("length", 0)
            for e in pastes
        )
        
        duration = session.get("duration", 1)
        stability = session.get("stability", 100)
        
        rows.append({
            "candidateId": session.get("candidateId"),
            "candidateName": session.get("candidateName"),
            "repoId": session.get("repoId"),
            "durationSec": duration,
            "stabilityScore": stability,
            "pasteCount": len(pastes),
            "totalPastedChars": total_pasted_chars,
            "focusLostCount": len(focus_losses),
            "testExecutions": len(tests),
            # Label: 0 = Autonomous Developer, 1 = High AI Plagiarism Risk
            "integrityRiskLabel": 1 if total_pasted_chars > 120 or len(focus_losses) >= 3 else 0
        })
        
    df = pd.DataFrame(rows)
    return df

if __name__ == "__main__":
    df = extract_features()
    print(df.head())
    df.to_csv("telemetry_features.csv", index=False)
    print("Exported to telemetry_features.csv")
```
